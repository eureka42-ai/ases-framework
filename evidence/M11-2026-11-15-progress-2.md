# M11 progress 2 — injection boundary and safe logging

Date: 2026-11-15

## Scope

- AFR-089: keep prompt-like tool/RAG content from changing policy.
- AFR-090: redact secrets and sensitive data before logs reach a sink.

## Implementation

- Policy rules are copied into a frozen snapshot. Tool/RAG result text is not an input to policy evaluation; an instruction-like returned document cannot grant workspace, network, or command permissions.
- Added `createSafeLogRecord()` and `writeSafeLog()`. The sink receives only bounded JSON after field-key and text-pattern redaction; errors omit stacks, binary data is omitted, and cyclic/deep/oversized payloads are bounded.
- Shared redaction covers provider tokens, bearer credentials, credential URLs/assignments, private-key blocks, email addresses, and SSNs. Moved the redactor into a reusable export and used it for ContextBundle exports as well.
- Updated M11 backlog criteria and added logging/security documentation. Backlog is 85/140 implemented and 55/140 pending.

## Limits

- A host must route dynamic log data through the safe logger; the module cannot sanitize writes made outside its API.
- Secret/PII recognition is heuristic, not exhaustive. Safe logging does not justify collecting unnecessary personal data.
- Policy separation protects authorization state, but host/model integrations must still treat retrieved text as untrusted instructions and preserve their own system policy boundaries.
