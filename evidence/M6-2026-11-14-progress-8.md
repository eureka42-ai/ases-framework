# M6 progress 8 — concurrent call budget

Date: 2026-11-14

## Implemented

Added `CallBudget`, which validates a finite non-negative limit and reserves each estimated call cost synchronously before dispatch. This closes the race where concurrent calls could each pass a separate preflight check. A call that would cross the limit is rejected with `BUDGET_EXCEEDED` before the provider is invoked. Reservations remain consumed after an ambiguous provider failure to avoid accidental overspend.

## Verification

Automated coverage confirms a concurrent second request is blocked before provider dispatch and that zero budget blocks a positive-cost call. Full suite and CI will be recorded before closing this requirement.
