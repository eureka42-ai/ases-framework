# M15 progress 23 — frontend quality review agent

Date: 2026-11-15

## Delivered

- Added `reviewFrontendQuality` and `createFrontendQualityAgent`, exported from the CLI package.
- The reviewer scores supplied LCP, INP, and CLS observations separately for mobile and desktop. Field data is only classified at p75; lab data is shown as context and never counts toward field coverage.
- Axe violation summaries become deterministic findings by impact. A blank list counts as an audit only when `axeAuditComplete` is true. `clear` requires six field metrics, a completed axe audit, and completed manual accessibility review.
- Input validation bounds records and observations; HTTPS/HTTP URLs with credentials are rejected, query parameters and fragments are removed, and reports expose only axe rule IDs, impact, and node counts.
- The agent declaration has no workspace, network, or command permissions and zero cost. The evaluator does not open URLs, launch scanners, call a model, or edit files.
- Guidance and thresholds are documented in `docs/agents/frontend-quality.md`. Reference thresholds: [web.dev Web Vitals](https://web.dev/articles/vitals), [threshold definitions](https://web.dev/articles/defining-core-web-vitals-thresholds), and [Lighthouse accessibility scoring](https://developer.chrome.com/docs/lighthouse/accessibility/scoring).
