# M5 — progresso 8: lifecycle local dos adapters — 2026-11-14

## Implementação

- `ases host apply <host> <workspace>` mostra um plano sem escrever; somente `--apply` aplica no workspace indicado.
- Conflitos interrompem antes da primeira gravação; destinos são criados exclusivamente, sem sobrescrever arquivos existentes.
- Claude Code prepara Skill e comando de projeto em `.claude/skills/` e `.claude/commands/`. O plugin nativo permanece disponível pelo marketplace e `--plugin-dir`.
- Codex, Kimi e Gemini preparam os artefatos locais definidos para cada adapter.
- Cada instalação guarda hashes dos arquivos e lista de diretórios que criou em `.ases/host-install-<host>.json`.
- Arquivos idênticos compartilhados por adapters são registrados como emprestados. As referências ativas impedem que o adapter proprietário remova uma Skill usada por outro; após remover o último adapter consumidor, repita o comando de remoção do proprietário para excluir seus arquivos.
- `ases host uninstall` é read-only por padrão; `--apply` remove apenas arquivos regulares ainda idênticos ao hash, diretórios vazios comprovadamente criados pelo adapter e o manifesto válido. Arquivos alterados, dados adicionais e `.ases/` preexistente são preservados.
- Falhas durante a aplicação removem os arquivos recém-criados ainda intactos e tentam retirar os diretórios vazios criados pela operação.
- Nenhum caminho de configuração global dos quatro hosts é escrito.
