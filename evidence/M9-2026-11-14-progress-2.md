# M9 progress 2 — RAG filters, refresh, and project access

Date: 2026-11-14

## Scope

- AFR-071: filter by license, version, and ACL.
- AFR-072: refresh changed and removed sources.
- AFR-074: deny cross-project reads without explicit permission.

## Implementation

- Source metadata now stores license, version, and an optional principal allowlist. Search and exact-ID retrieval accept exact-match license/version filters and enforce the ACL. `rag:acl:bypass` is an explicit capability.
- Each index is bound to a project ID. A query with a different project ID raises `RagAccessError` unless its trusted host context includes `rag:cross-project`.
- `refreshRagIndex()` re-hashes and re-chunks changed files, preserves source metadata, drops removed paths, and fails closed on unsafe or unreadable paths.
- Exported the RAG APIs and types from the package entry point; added `dist/rag.js` and its declaration to the npm tarball allowlist.
- Added API and security guidance in `docs/rag/offline-index.md`.
- Updated status, roadmap, README, and AFR-071/072/074 criteria. Backlog is now 72/140 implemented and 68/140 pending.

## Security boundary

- Host adapters must derive project IDs, principal IDs, and permissions from trusted authorization context. Prompt text or untrusted caller input must never grant `rag:cross-project` or `rag:acl:bypass`.
- The index remains in-memory. Persisted indexes need integrity validation and must not be shared across projects without rechecking their access context.
