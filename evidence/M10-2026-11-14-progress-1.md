# M10 progress 1 — consented memory and ContextBundle

Date: 2026-11-14

## Scope

- AFR-077: memory scope, TTL, consent, and provenance.
- AFR-078: inspect and effectively delete stored memory.
- AFR-079: export selected decisions, requirements, and checkpoints.
- AFR-080: reject inconsistent source and bundle hashes.
- AFR-081: redact recognized secrets before export.

## Implementation

- Added local `remember`, `inspectMemory`, and `forgetMemory` APIs. Storage is workspace-scoped, split between session/project directories, requires explicit consent and origin, enforces a bounded TTL, creates private files exclusively, checks integrity, hides expired records by default, and removes entries from disk on deletion.
- Added `createContextBundle` and `verifyContextBundle`. Bundle creation accepts only selected records, validates their original content hashes, applies pattern-based redaction to content/title/path, counts redactions, and hashes the resulting bundle. Verification detects post-export mutation.
- Exported the memory and ContextBundle APIs from the package entry point and included `dist/memory.js` and declarations in the npm package allowlist.
- Added developer documentation and tests for consent, scoping, expiry, disk deletion, secret redaction, source hash rejection, and bundle tampering.
- Backlog is now 77/140 implemented and 63/140 pending; AFR-082/083 remain in M10 for safe import preview and archive handling.

## Limits

- Memory is local and file-based. No cloud sync, encryption-at-rest layer, or automatic purge scheduler is included.
- Redaction is pattern-based and cannot guarantee detection of every secret; review exported bundles before sharing.
- Bundle SHA-256 detects mutation but is not a signature or proof of authorship.
