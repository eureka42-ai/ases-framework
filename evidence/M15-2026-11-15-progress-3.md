# M15 progress 3 — capability-based tool discovery

## Implemented

- Runtime tools may declare optional, unique lowercase capability identifiers such as `repository.search` and `file.read`.
- Exported `rankToolsByCapabilities(tools, required)` returns deterministic candidate metadata: coverage score, matched/missing capabilities, compatibility and side-effect status. Compatible tools rank first; partial matches remain visible with their gaps.
- Duplicate tool names and invalid/duplicate capability declarations fail closed. Plugin contract validation checks capability metadata as well.
- Discovery is descriptive only. It neither runs a tool nor authorizes it; every invocation still goes through `executeTool()` and its explicit policy decision.
- Documented the API and marked AFR-115 implemented with linked artifacts and tests.

## Limits

Ranking is based only on capability declarations supplied by the runtime/plugin author. It does not prove that a tool's implementation fulfills those declarations and is not a permission grant. Plugin contract tests and the execution policy remain separate checks.
