# M15 progress 4 — reproducible provider benchmark

## Implemented

- Added the public `runModelBenchmark()` API for caller-supplied provider adapters and versioned local fixtures.
- Every provider call requires `enabled: true`; the default returns a skipped report without invoking an adapter. Runs are sequential and bounded by provider, fixture, repetition, total-call and timeout limits.
- Fixtures support prompt/system instructions, output-token limits and exact `expectedAny` checks. A SHA-256 fingerprint covers fixture IDs/versions, prompt/system hashes, token limits and scoring criteria; provider IDs, timeout and repetitions are included in the report.
- Summaries group by observed provider/model and expose PASS/FAIL/ERROR/SKIPPED, success rate over scorable cases, mean/p95 latency and reported token totals with observation counts. Missing evaluation criteria or usage remain unscored/unknown.
- Reports omit prompt and response text, sanitize provider errors to error codes and never estimate prices. Added package exports, package allowlist, Portuguese/English guidance and AFR-116 traceability.

## Limits

The default evaluator checks exact substrings only; it is not semantic quality grading. The framework ships no live model adapter. Provider latency, outputs and reported usage can vary across remote service versions and operating conditions; the fixture hash makes inputs comparable but cannot guarantee identical external behavior. Cost is intentionally not estimated.
