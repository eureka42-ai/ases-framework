# M11 progress 1 — default-deny policy and command/path guard

Date: 2026-11-15

## Scope

- AFR-086: enforce a default-deny security policy.
- AFR-087: block traversal, symlink escapes, and hostile shell/dynamic command plans.

## Implementation

- Added `SecurityPolicyEngine`: unmatched requests deny; explicit deny overrides allow; actor, action, and resource constraints are exact.
- Every runtime tool now requires an explicit authorization decision, including tools marked read-only. The shared policy engine is supported directly; host callbacks remain available as explicit authorization decisions.
- Added `authorizeCommand()` as a plan validator, not an executor. It requires an exact executable+argv signature, rejects shell executables and interpreter eval flags, rejects `..` path arguments, and validates `cwd` inside the canonical workspace through the existing symlink-aware path guard.
- Exported the engine and command APIs from the package entry point and included their JS/types in the npm package allowlist.
- Updated M11 criteria and docs. Backlog is 83/140 implemented and 57/140 pending.

## Verification

- `pnpm test`: PASS; build succeeded, 99/99 tests passed, integration validation passed (4 manifests, 2 marketplaces, 6 Skills).
- `npm pack --dry-run ./packages/cli`: PASS; inventory contains `dist/policy.js`, declarations, and package entry-point exports.
- Tests cover default deny, deny-overrides, actor/resource matching, exact command signatures, shell/eval rejection, traversal, symlinked cwd, and tool gating before handlers run.

## Limits

- `authorizeCommand()` does not run a process. Any future runner must use a no-shell API and add environment, timeout, output, and just-in-time authorization controls.
- The security policy remains enforced only at boundaries that call the engine; a host must supply actor identity and must not derive permissions from untrusted prompt text.
