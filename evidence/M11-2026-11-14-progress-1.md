# M11 progress 1 — evidence context and current eligibility

Date: 2026-11-14

## Scope

- AFR-084: require evidence hashes and execution context.
- AFR-085: keep stale, missing, expired, or unverifiable evidence from making a requirement eligible.

## Implementation

- `VERIFIED` now requires an in-workspace evidence file and a nonempty `--execution-context`. The evidence record includes SHA-256, capture time, Node version, platform, test references, and optional future expiry via `--evidence-expires-at`.
- `readCatalog()` recalculates evidence state on every read. It exposes `verificationEligibility`; at least one current, unexpired, contextualized workspace-file evidence is required.
- `show`, `list`, and `trace` surface eligibility. Stale, missing, expired, outside-workspace, and unverifiable evidence does not qualify.
- Added regression coverage for missing context, current evidence, expiration, modification, deletion, and trace output. Added command documentation and updated AFR criteria.
- Backlog is now 81/140 implemented and 59/140 pending.
