# M15+ progress 20 — visual workflow editor

Date: 2026-11-15

## Delivered

- Added `packages/workflow-editor`, a local React/Vite application for authoring workflow DAGs. It edits workflow and step names, step kind, agent/handler, dependencies, timeout and declared permissions; adds, removes and reorders steps; and shows the dependency graph and selected step properties.
- Drafts save to browser-local storage. JSON import/export uses the workflow root shape with `schemaVersion: "1"`.
- “Run preview” validates the deterministic topological order and shows a dry preview. It does not invoke agents, commands or tools. Invalid cycles are rejected by the same workflow validator.
- Workflow metadata is part of the definition hash and is exposed to the executor through `WorkflowExecutionContext`. The executor host remains responsible for applying declared permissions and timeout values.
- Added the generated visual concept at `docs/design/workflow-editor-concept.png` and linked the editor guide from the repository README.
- Supply-chain license inventory now recognizes `CC-BY-4.0`, declared by the private editor build's `caniuse-lite` data dependency. The package is not part of the CLI runtime tarball; its upstream license is retained with the development dependency and documented in `THIRD_PARTY_NOTICES.md`.

## Visual verification

The Browser plugin host was unavailable in this session. Used Playwright with the installed system Google Chrome in headless mode against the local Vite server as the fallback.

Screenshots captured at 1440×1000 desktop, preview dialog, and 390×844 mobile. Compared the concept and implementation at these points:

1. Eureka42 wordmark, green accent, and left navigation rail.
2. Workflow breadcrumb/title and save/preview controls in the top bar.
3. Three-column steps, graph canvas, and properties inspector proportions.
4. Centered DAG nodes, dependency arrows, selected-node green treatment, and graph controls.
5. Inspector field hierarchy and spacing for name, agent, dependencies, timeout, and permissions.
6. Mobile layout collapses navigation and editor panels into a single column without horizontal overflow.

The concept depicts drag handles and a grouped read/write permission panel. The implementation instead provides explicit reorder buttons and a flat list of named granted scopes, plus JSON import/export controls. These are deliberate interaction differences; the graph, property editing, branding, and hierarchy match the concept.
