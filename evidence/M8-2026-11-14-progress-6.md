# M8 progress 6 — idempotency contract and green CLI opening

Date: 2026-11-14

## Scope

- AFR-065: provide a stable idempotency key to workflow step handlers marked with `sideEffect.strategy: "idempotent"`.
- Improve the first CLI impression for all supported host integrations.

## Implementation

- `executeWorkflow` passes a deterministic key composed of workflow ID, SHA-256 of the full canonical workflow definition, and step ID.
- The definition hash includes side-effect metadata so strategy changes invalidate checkpoints and keys.
- `ases welcome --color` forces the green Eureka42 mark for plugin startup even when stdout is captured. Normal `ases welcome` continues to respect TTY, `NO_COLOR`, and `TERM=dumb`; explicit `--no-color` takes precedence.
- Codex, Claude Code, Kimi, and Gemini entrypoints call `ases welcome --color` as their first terminal action. Six distributed copies of the shared onboarding Skill are checked for synchronization.
- Integration validation requires the explicit green command in each Skill and host entrypoint.

- Added logo tests for green ANSI output, terminal/color environment support, and `--no-color` precedence.

## Scope and limitation

The workflow runtime supplies an idempotency key; the external adapter/handler must forward it and the destination service must enforce deduplication. This implementation does not claim exactly-once external effects. Host session rendering of the startup logo has not yet been smoke-tested in authenticated conversations.
