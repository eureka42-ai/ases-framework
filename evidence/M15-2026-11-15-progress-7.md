# M15 progress 7 — team policy as code

## Implemented

- Added versioned JSON team policies with an immutable `defaultEffect: deny`, known actions/effects, stable unique rule IDs, required rationales and explicit scope for allow rules.
- `command.execute` requires an exact serialized command resource. Matching allow/deny overlap is reported; the policy engine's explicit-deny precedence remains in force.
- Added `ases policy template`, `policy validate <file>` and `policy evaluate <file> --actor ... --action ... --resource ...`. Evaluation simulates a decision and does not run the requested tool or command.
- Policy file reads reject final symlinks and files over 1 MiB. Added public SDK helpers, CLI tests and team guidance for version control/review.
- Implemented AFR-125 with linked code, docs and tests.

## Limits

Resource matching is exact; prefix and wildcard authorization are not implemented. A successful `policy evaluate` result is only a simulation. Actual tool execution must still use the policy-aware runtime, and command plans must continue through `authorizeCommand()` checks.
